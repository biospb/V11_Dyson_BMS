# September–October 2026 audit follow-up

Target: `V11_Dyson_BMS_fork`, based on `ceaf179`. No device was flashed.

## Voltage ownership

`bq7693_get_cell_voltages()` reads fresh hardware values. It updates a separate
last-good RAM snapshot only when all seven register reads succeed. Failed
reads still report zeroes to existing safety callers and latch the I2C error;
they never replace the telemetry snapshot with a partial or failed reading.

`bq7693_get_cached_cell_voltages()` returns that snapshot without I2C or changes
to the communication latch. It returns NULL before the first complete read.
Its pointer is for main-loop use, before another fresh read or service call;
it is not an atomic ISR interface or a freshness guarantee.

The snapshot is seeded at boot. Existing protection, balancing and wake/top-up
reads refresh it. DSN TLVs, ordinary voltage logs and unplug balance indication
use it. The DSN frame analyzer does not pump services between TLVs, so the frame
uses one coherent snapshot without a second seven-cell RAM buffer. Unavailable
cell TLVs are omitted until a complete snapshot exists. Logged pack voltage is
now the sum of cached cells, not a separate BAT-register measurement.

Datasheet check: BAT is not an independent pack-voltage ADC. TI SLUSBK2I
section 8.3.1.1.6 (page 21) defines it as the digital sum of cell conversions,
divided by four; conversion back to voltage uses the same GAIN and per-cell
OFFSET. SLUUB41A section 4.2 (page 9) confirms this explicitly. Thus using BAT
does not remove the cell ADC measurement errors. It can differ from the host
sum because of integer rounding, different update/read times and inclusion of
unused VC channels; those are possible explanations, not a measured diagnosis
of this pack's observed discrepancy. The host cache contains the seven mapped
channels, not a hardware-latched simultaneous acquisition of all channels.

Sources: [TI datasheet](https://www.ti.com/lit/ds/symlink/bq76930.pdf#page=21),
[TI AFE FAQ](https://www.ti.com/lit/ug/sluub41a/sluub41a.pdf#page=9).

Charge termination reuses the snapshot from the immediately preceding safety
check (`bms_is_pack_full(false)`). Standalone checks, including after standby,
request a fresh read (`true`). Protections and balancing retain fresh reads.

## Disposition of the supplied findings

| Item | Result |
| --- | --- |
| 1, 5, 8 | Already mitigated at the driver layer: three write attempts, each with bounded packet retries. After exhaustion, preserve FAULT; unconfirmed CC acknowledgement or FET-off must not be treated as success. |
| 2 | Noflow checks communication health before interpreting cells. Bus failure stops charge and faults instead of shutting down on fabricated zeroes. Low-voltage noflow shutdown requires three consecutive valid observations, separated by the normal loop. |
| 3 | Near-full noflow has at most three timeout windows (15 minutes with current constants) without charge-current recovery. It then uses normal completion, storage-mode handling and EEPROM commit. Fresh safety checks still run before completion. |
| 4 | DSN cell/min/max voltage TLVs use RAM only; telemetry no longer initiates I2C or forces an I2C fault. |
| 6 | Retry only invalid ADC conversions, at most three per sensor per sampling operation. Keep valid readings, including hot/cold readings, during retries of the other sensor. Persistent invalid data still prevents charge, discharge and balancing. |
| 7 | Docked fault giveup enters MCU standby retaining the fault, rather than SHIP/reset. Charger, mode, trigger or RTC wakes it for recovery checks. This does not repair an electrically stuck bus or guarantee low AFE draw. |
| 9 | Calculate SOC to the protocol's 0.01% resolution without early truncation or 64-bit division. Preserve the intentional zero-SOC signal during discharge/UV faults. Cleaner reaction remains a hardware check. |
| 10 | CRC/layout-valid pages are normalized field by field when policy upper bounds or STORAGE_IDLE_WAKES change. Preserve learned capacity and upward-learning charge counts. Shadow retains actual flash values so normalization is committed later. Bad CRC, wrong layout marker, negative charge/nonpositive capacity and invalid boolean remain rejected. Older firmware cannot be made migration-safe by this firmware. |
| 11 | Up to three write/commit/readback attempts. Readback is necessary because ASF's commit function returns STATUS_OK without propagating physical NVM write status. Persistent failure still invalidates persistence health. |
| 12 | Remove the automatic CTRL2/STAT debug readback from FET enable. Ordinary voltage diagnostics use cache; the raw ten-channel diagnostic API remains available for deliberate cell-map investigation. |
| 13 | Leave 25/15/20 mV START/STOP/TARGET unchanged. Choosing different thresholds or per-group corrections requires calibrated measurements across packs; one observed offset does not establish a universal replacement. |
| 14 | Preserve the existing AFE/I2C fault class and explicit ALERT log. Do not add an unverified held-ALERT electrical test or renumber LED codes. Safety must continue to reject OVRD_ALERT while charging. |
| 15 | After disabling FETs and waiting one second, qualify empty on fresh, readable, plausible relaxed cells. Recovered load sag preserves the coulomb count and clears the full-discharge learning marker. Confirmed relaxed low voltage sets the marker and zeroes the gauge. |
| 16 | Snapshot the fault code and consume the request in one critical section. A later watchdog interrupt remains pending. |
| 17 | Keep the existing GCC/C99 toolchain and assertion. Porting to another compiler is outside this change. |
| 18 | Build with ARM GCC/LTO and inspect the linked vector table and ISR symbols. Actual interrupt delivery, standby wake and electrical FET operation require hardware. |

## Reproducible checks

From repository root in an environment with Python 3 and a native C compiler:

```sh
python3 tests/host_regressions.py
cmake -S V11_BMS -B V11_BMS/build-audit -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE=cmake/arm-none-eabi.cmake -DCMAKE_BUILD_TYPE=Release
cmake --build V11_BMS/build-audit
git diff --check
```

Host tests compile the production C functions with fault-injected dependencies:
complete/partial/unavailable cache and zero telemetry transfers, independent
ADC retry and preserved valid heat, SOC against a 64-bit reference, EEPROM
readback/retry/migration, noflow bus failure/debounce/bounded taper/storage mode,
and relaxed-empty learning versus load sag/broken tap/bus failure. These tests
do not emulate the MCU, peripheral timing or the complete firmware state machine.

All six suites passed. ARM GCC 10.3.1 / LTO linked both configurations:

| Configuration | Flash (.text + .data) | RAM including reserved stack/alignment |
| --- | ---: | ---: |
| Current SERIAL_DEBUG configuration | 29,812 / 30,208 bytes | 4,096 / 4,096 bytes |
| SERIAL_DEBUG=0, PROT_DEBUG_PRINT=0 | 22,692 / 30,208 bytes | 3,544 / 4,096 bytes |

The current build retains a full 2,048-byte stack, but has no unallocated RAM
above it. Stack consumption inside that reservation has not been measured.
Both builds report the existing ASF/newlib `__always_inline` redefinition warning.
`git diff --check` passed. The vector table is linked at address zero, with
initial SP 0x20001000 and verified Reset, WDT, EIC and TC0 handler addresses.

## Subsequent size-only consolidation

The two charge/discharge status lines share one function and format string.
BMS_PRINT and DSN_PRINT then share `serial_debug_printf()`, which keeps the
same bounded 128-byte local buffer, queue semantics and compiler format
checking. Disabled log macros still discard arguments without evaluating them.
It supports both tiny_vsnprintf and the existing libc fallback. No global
logging buffer or service pumping was added.

Identical charge-stop sequences share a helper, preserving FET/balancing/LED
order. Duplicate GPIO-low writes immediately before `bms_fet_off(true)` were
removed because that owner already lowers the GPIO before the I2C operation.
The helper also handles terminal exits where balancing or LED cleanup was
previously implicit: initial safety refusal, charge-enable/resume failure,
noflow communication failure, EEPROM failure, unplug, completion and FAULT.
Temporary charge pauses retain their separate FET-off operation so balancing
can continue during the pause.

Measured ARM/LTO flash usage (.text + .data):

| Step | Bytes | Saving from previous step |
| --- | ---: | ---: |
| Audit fixes | 29,812 | — |
| Shared status line | 29,596 | 216 |
| Shared BMS/DSN formatting | 29,020 | 576 |
| Charge-stop consolidation | 28,916 | 104 |
| Single-call cached voltage/capacity logs | 28,852 | 64 |

Total saving is 960 bytes; allocated RAM and 2 KiB stack reservation are
unchanged. The no-log build uses 22,556 flash bytes (136 fewer than before).
Seven host suites pass, including shared-log formatting and truncation, and
both ARM/LTO configurations link. This remains a software-only verification.

Cached voltage output now uses one `serial_debug_printf()` call instead of
seven per-cell formats plus a suffix; capacity output uses the same formatter.
The former `tmp[30]` buffers were bounded and sufficient for normal values,
not an observed overflow. The complete voltage line fits the existing
128-byte formatter even for seven UINT16_MAX values; host checks verify its
full text, unavailable-cache handling and capacity output. The formatter's
128-byte buffer replaces the local temporary; this is a flash saving, not a
claim of lower peak stack usage.

## Hardware acceptance still required

- Exercise motor start/stop, maximum load and real UV sag; verify that a partial
  cycle cannot become the next learned full capacity.
- Exercise transient and sustained bus failures, CC ACK and FET teardown.
- Request DSN cell/min/max values before and after a failed refresh; confirm
  no request-triggered I2C traffic and correct cleaner handling of SOC zero.
- Check taper completion and a disconnected/dead charger in both normal and
  storage modes, including a pack just above/below the release threshold.
- Hold the docked fault until giveup; confirm standby current, retained fault,
  all wake sources and recovery without repeated resets.
- Measure inter-group AFE offset against a calibrated meter before changing
  balance thresholds. Test ISR delivery and wake on the actual LTO firmware.
- RAM is 4 KiB on the configured SAMD20E15. The linker reserves 2 KiB for stack;
  that reservation is retained. Check stack high-water under combined debug,
  fault and DSN traffic before calling the firmware hardware-validated.
